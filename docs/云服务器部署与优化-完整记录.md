## 二、最终架构

```
微信 App
   ↕ (本机微信客户端 + hook 注入)
Weixin.exe 4.1.10.27  ──30001──►  adapter (8766)
                                      │
                                      ├── reader (5031)  读微信数据库
                                      └── bridge (11229)
                                              │
                                      桥接插件 (11230)
                                              │
                                        DSH web (3080)
                                              │
                                       DeepSeek API
```

| 端口 | 服务 | 说明 |
|---|---|---|
| 30001 | WeChat-Hook | 注入在微信进程内，出 HTTP 接口 |
| 5031 | reader | 读数据库（WeFlow） |
| 8766 | adapter | 消息桥接，接微信 ↔ bridge |
| 11229 | bridge | OneBot 适配层 |
| 11230 | 桥接插件 | DSH 侧插件，`/health` 与 `/skills` |
| 3080 | DSH web | 网页端（带 token） |
| 3389 | RDP | 远程桌面 |

全部只监听 `127.0.0.1`，靠 SSH 隧道访问，不对公网暴露。

## 四、踩过的 12 个坑（现象 → 根因 → 解法）

### 1. 工作区写入被拒
- 现象：`SetNamedSecurityInfoW failed (Win32 5): grantWrite`
- 根因：`D:\deep seek工作区` 缺少当前用户的完全控制权，沙箱无法授权
- 解法：跑官方 `diagnose-windows-sandbox-acl` 脚本修复（已备份 + 打印回滚命令）

### 2. bash 起不了 ssh
- 现象：`cannot create standard input pipe for ssh: Permission denied`
- 根因：沙箱限制命名管道
- 解法：所有 `git`/`ssh` 操作改用 pwsh 执行

### 3. 没有 npm / pnpm
- 现象：`npm 不是内部或外部命令`；装插件时 `'pnpm' 不是内部或外部命令`
- 根因：Server 镜像干净，DSH 的 `plugin` 命令要转发给 pnpm
- 解法：先装 Node（npmmirror 的 msi），再 `npm i -g pnpm@10`

### 4. 服务注册 1053
- 现象：`sc create` 后 `StartService 失败 1053`
- 根因：node 不实现 SCM 握手协议
- 解法：放弃服务方式，改计划任务 + WMI 创建进程

### 5. 进程被任务回收
- 现象：任务显示成功（结果 0），但 node 进程几十秒后消失；或结果 `0xC000013A`
- 根因：任务结束时 job object 连带回收子进程 / 控制台关闭发送 CTRL_CLOSE
- 解法：任务只跑一个**极短脚本**，用 `Win32_Process.Create`（WMI）拉起真正进程 —— 归 WMI 所有，不受任务生命周期影响

### 6. SYSTEM 跑 DSH 不监听
- 现象：进程在、日志空、3080 一直不 bind
- 根因：与 5 同类（父进程退出/环境不同），未深究
- 解法：任务改为 `Administrator` + `/IT` 交互式，和微信同会话

### 7. 微信版本不匹配
- 现象：用户提供的 4.1.15 装不上/不认
- 根因：代码写死 `expectedVersion === '4.1.10.27'`，hook 偏移量按该版本编译
- 解法：改用 WeChatAgent 自带 `vendor\wechat\4.1.10.27`，删除 4.1.15 安装包

### 8. 微信启动即退出（-1）
- 现象：`Weixin.exe` 一启动就返回 -1，无崩溃日志
- 根因：**系统缺 VC++ 运行库**（System32 里没有 `vcruntime140`/`msvcp140`）
- 解法：把程序自带 DLL 复制进微信目录（临时），后装官方 `vc_redist.x64`（彻底）

### 9. 读取组件加载失败
- 现象：`READER_KEY_COMPONENT_MISSING`
- 根因：`wx_key.dll` 加载失败，同样是缺 VC++ 运行库
- 解法：装 `vc_redist.x64` 后，`ctypes.CDLL(wx_key.dll)` 验证通过（`DLL_LOAD_OK`）

### 10. 客户端目录拒绝写入
- 现象：复制 `version.dll` 报「访问被拒绝」
- 根因：插件故意给客户端目录加了 **deny ACE**（pin，防微信自动更新覆盖 hook）
- 解法：`icacls <dir> /remove:d Administrator` 解锁 → 写入 → 由插件重新 pin

### 11. 配置文件 BOM 导致启动失败
- 现象：`Unexpected token 'v', "v..." is not valid JSON`
- 根因：用 PowerShell 5.1 的 `Set-Content -Encoding UTF8` 写文件，**自动加了 BOM**
- 解法：统一用 `[IO.File]::WriteAllText(path, text, UTF8Encoding($false))`

### 12. 微信收得到消息但不回
- 现象：adapter `received=1`、`confirmed_sends=0`
- 根因：DSH 没有模型凭据（provider `deepseek-account` 未登录，`.credentials.yaml` 里只有浏览器会话密钥）
- 解法：在 DSH 网页端登录 DeepSeek 账号（或改用 API Key provider）

## 五、成本优化专项（摘要）

问题：桥接插件每轮都用 `surfaceOp: replace` 改写历史，prompt 前缀每轮都变，DeepSeek 前缀缓存命中率 ≈ 0，等于每轮重开。

改动 6 处：

| # | 位置 | 改动 |
|---|---|---|
| 1 | `native-context.mjs:437` | 不再 `dedupePreviousReply`（回头删上一条） |
| 2 | 同上 `:424` | 轮次指令槽改为拼进本轮消息**尾部** |
| 3 | 同上 `:393` / `:605` | 移除两处 `retireTurnContext`（替换历史为「已清理」） |
| 4 | 同上 `:440` | 搜索上下文 `unshift`（插最前）→ `push`（追加尾部） |
| 5 | 配置 | 上下文上限 100k → 30k；压缩阈值 30k、空闲 60s 触发 |
| 6 | 同上 | 移除单聊 100k 覆盖（会让阈值失效） |

验证数据：

- **前缀稳定性**：连续 7 轮 `prefixHash` 完全一致（`0a7f6be8b8cc8ce7`），系统头摘要恒定
- **压缩有效性**：阈值临时降至 12000 后触发一次，历史 183,999 → 17,247 字符（↓91%），哈希变化一次后重新稳定

> 详细步骤与勾选清单见 [微信桥接-缓存优化方案.md](./微信桥接-缓存优化方案.md)。

## 六、运维手册

### 启动（重启服务器后）

1. RDP 登录服务器（**必须**，两个任务都是 `ONLOGON` 交互式）
2. 任务 `DSHWeb` 自动起来；没起来就手动 `schtasks /Run /TN DSHWeb`
3. 打开 WeChatAgent 控制台 → 点「启动服务」

### 自检三件套

```powershell
# 1) 端口
Get-NetTCPConnection -State Listen | Where-Object { $_.LocalPort -in 3080,11230,8766,11229,5031,30001 }

# 2) 适配器
Invoke-RestMethod http://127.0.0.1:8766/status

# 3) 桥接
$t = (Get-Content C:\Users\Administrator\AppData\Local\Programs\WeChatAgent\data\workspace\state\social-dsh-token.txt -Raw).Trim()
Invoke-RestMethod http://127.0.0.1:11230/health -Headers @{ Authorization = "Bearer $t" }
```

### 从本机访问

双击工作区里的本地脚本「连接微信助手.cmd」（含服务器地址，未纳入仓库）：自动探测控制台端口、建三条 SSH 隧道（控制台 / DSH / RDP），并打开页面。

### 日志位置

| 文件 | 内容 |
|---|---|
| `C:\dsh\web.log` | DSH 启动与 token |
| `data\workspace\state\logs\*.log` | adapter / bridge / reader |
| `data\workspace\state\hook-init.log` | 微信 hook 注入过程 |
| `data\workspace\state\usage-log.jsonl` | 每轮前缀哈希与历史长度（本次优化新增） |

### 回滚

- 桥接插件：`...packages\dsh-social-bridge-plugin.bak-20261024-112420`
- 配置：`config\wechatagent.json`（改动前有 `wechatagent.example.json` 可参照）

## 八、经验沉淀（可复用）

1. **Windows 上让程序常驻**：别用 `sc create` 直接跑 node（1053），也别用计划任务直接跑长进程（会被 job 回收）。用「任务 → 极短脚本 → WMI 创建进程」最稳。
2. **Server 镜像默认缺 VC++ 运行库**，任何 C++ 程序（微信、原生 DLL）都先装 `vc_redist.x64`。
3. **PowerShell 5.1 的 `Set-Content -Encoding UTF8` 会加 BOM**，写 JSON 必炸；用 `UTF8Encoding($false)`。
4. **不要用正则改 JSON 结构**：`{[^}]*}` 会被嵌套对象打断。用解析器，或精确定位唯一字面量。
5. **DeepSeek 前缀缓存的唯一要求是「前缀逐字节一致」**：任何"回头改历史"的设计（去重、清理、插槽）都会让成本翻 50 倍。
6. **度量要对**：拿「本轮新增消息」做哈希是错的，要拿「会话真实 surface」做哈希，且长度必须固定才可跨轮比较。
